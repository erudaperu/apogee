# My roadmap

I will work through evidence-based milestones. I have not assigned dates because my budget, equipment access and weekly time are not fixed yet.

| Milestone | Hardware / physical work | Software work | Exit evidence |
| --- | --- | --- | --- |
| M0 — Define | Inventory tools; choose a provisional packaging concept | Choose data fields and a replay format | Requirements, interface draft and decision list |
| M1 — Connect the idea | Compare candidate boards and sensors; sketch mounting | Generate synthetic records; build parser and replay | Reproducible demo, parser tests and hardware shortlist |
| M2 — Measure on the bench | Assemble a non-flight sensor test setup | Implement acquisition, health flags and logging | Bench recording, setup photos and fault results |
| M3 — Integrate | Fit-check the avionics enclosure and document assembly | Connect recordings to ground display and offline analysis | Integration notes, replay capture and test report |
| M4 — Review for model-rocketry use | Review mechanical suitability and a supervised launch route | Freeze a documented logging configuration | Readiness review with unresolved items stated |
| M5 — Observe and compare | Optional model-rocket field trial after the review | Compare observations with predictions | Attributed field record and discrepancy report |

**Current milestone: M0 — planning.** The later milestones describe intent, not completed work or a launch commitment.

## My first work session

- [ ] List the boards, sensors, tools and software I already have.
- [ ] Set a budget ceiling and a realistic weekly time allocation.
- [ ] Choose the first three measurements I want to inspect.
- [ ] Draft one example record with units and validity fields.
- [ ] Define a single replay use case: load, pause, inspect and export.
- [ ] Compare two feasible avionics configurations against that use case.
- [ ] Record the decisions and the next smallest task in the journal.

## How I will keep the scope manageable

I will add wireless telemetry, a custom PCB or AI only when it solves a documented limitation of the current milestone. A polished replay tool and a reliable bench logger are worthwhile results on their own. I will not make the value of the project depend on a launch.
